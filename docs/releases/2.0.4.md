# oh-my-multica v2.0.4

A patch release for the command a review-budget stop tells you to run.

## Fixed

- **`omac plan continue-review` refused the stop that named it.** A `plan resume` that reached the review budget with a final
  delivery awaiting re-review after `pass-with-nits` blocked the issue with `gate=review`, and told the caller to run
  `plan continue-review`. The command only recognized `gate=review-nits` on a blocked issue, so it failed with "not in an
  exhausted reject or final-nits state" and the plan could not continue. The command now authorizes one review-only round,
  and the next `plan resume` dispatches the Reviewer.
- **A machine-gate budget stop named the wrong command.** Its `decision_required.next_action` pointed at
  `plan continue-review`, which cannot release that stop. The field is now left out.

## Behavior to know

- A stop with no `reject` verdict is now recorded as `gate=review-nits`, `reason_code=review-nits-budget-exhausted`, including
  when the stop happens on entering review. A rejected delivery still records `gate=review`.
- Issues already blocked with `gate=review` and no verdict need no metadata edit. `plan continue-review` accepts them after
  upgrading.
- `dag run` and the `node` commands are unchanged. Their decisions already match `node retry`, `node abandon`, and
  `node accept-nits`.
