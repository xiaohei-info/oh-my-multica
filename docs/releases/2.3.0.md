# oh-my-multica v2.3.0

A minor release: a DAG develop node that passes review with nits no longer stops the whole graph.

## Behavior to know

- **A develop node's `pass-with-nits` is a pass by default.** The node merges and is `done`; its nits stay verbatim in the
  review report and the node evidence (`omac node show <manifest> <node>`: `evidence.review_verdict`,
  `evidence.review_report.nits`). Before, each such node blocked itself and cascaded every downstream node to `blocked`, and
  `dag run` exited 20 until someone ran `omac node accept-nits`.
- **New config `review.node_nits: accept|decide`** (default `accept`). `omac config set review.node_nits decide` restores the
  earlier stop and `omac node accept-nits`.
- **Unchanged:** plan, acceptance and decompose stages and amendments still stop on `pass-with-nits`; reject with an exhausted
  budget, review-convergence stops and Worker blockers still stop the node.
- **A stopped node blocks only what depends on it.** Independent branches keep being dispatched; `dag run` exits 20 only
  when no node is running. (This was already so; it is now documented and regression-tested.)
