# oh-my-multica v2.3.1

A patch release: a reviewed, CI-green PR is no longer left in `merging` because GitHub has not scored its mergeability.

## Behavior to know

- **`mergeStateStatus: UNKNOWN` on an OPEN PR no longer blocks the merge request.** GitHub computes mergeability lazily and
  can keep `UNKNOWN` for a long time after the base branch advances. OMAC used to treat that as an unreadable PR and wait, so
  a node merged only when a tick happened to see `CLEAN`. Now an OPEN PR with no auto-merge and not queued is requested once;
  the merge command decides whether it can merge, and a refusal uses the existing `retry.merge` bounce or block.
- **Unchanged:** a failed read (`gh` error, timeout, malformed output, missing `mergeStateStatus`) still keeps the node in
  `merging` without a request or a spent retry; a request is never sent twice for one PR (`intent` / `requested` markers);
  merged is still decided only by the observed `MERGED` PR.
- No new configuration.
