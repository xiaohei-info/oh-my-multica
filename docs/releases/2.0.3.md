# oh-my-multica v2.0.3

A patch release for the handoff from a Reviewer back to the author.

## Fixed

- **A running `plan resume` idled forever after a review.** After a `pass-with-nits` or `reject` verdict, the issue went to
  `todo` with no assignee and the foreground process logged nothing more; killing it and running the same `plan resume`
  dispatched the author at once. The process now redispatches the author itself. `plan create` was not affected by the
  idling, because only a resumed process carried the state that caused it.
- **A resume waiting on an active Run never noticed that Run ending.** It now re-reads the issue when the Run ends. If the
  Run ended without a submit on an in-progress issue, the issue blocks with `completed-without-submit` and no second Run
  starts.
- **A machine-gate retry could stop with `dispatch-run-not-observed`.** The wake did nothing while the author's own Run was
  still ending. The retry now starts after that Run has ended.
- **A `dag run` node could stay in review forever.** A Worker that redelivered before the Reviewer's previous Run ended got a
  review that started no new Run. The handoff to the Worker now waits for the Reviewer's Run to end.

## Behavior to know

- The plan pipeline dispatches an author only after every direct Run on the issue has ended, at its usual poll interval.
  While it waits, it logs one `rework_handoff_wait` event, and the issue stays unassigned.
- The wait lasts as long as the Run does. A Run that never ends is handled as before: cancel it on the platform, or use
  `plan resume --restart-active`.
- `dag run` and `dag tick` make the same check for a Worker handoff, and retry on a later tick. They log one
  `rework_handoff_wait` event per tick and spend no retry budget.
