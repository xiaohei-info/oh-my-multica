# oh-my-multica v2.1.0

A minor release that changes what `pass-with-nits` means in the plan pipeline and makes every plan stop release with the
command it prints.

## Behavior to know

- **`pass-with-nits` in plan, acceptance and decompose now stops for a decision** (exit 20,
  `review-nits-acceptance-required`). Before, the delivery was sent back to its author automatically and reviewed again;
  with reviewers that keep returning nits the pipeline never converged. The review it stands on is kept. Run
  `omac plan accept-nits --dag-key <stage-key>` to accept the nits, then `omac plan resume --plan-id <id>`; or
  `omac plan continue-review --dag-key <stage-key>` to send them back to the author (a counted round). Unattended callers that
  relied on the automatic rework must run one of these commands.
- `omac plan resume --plan-id <id>` needs no other argument for any pipeline created by 2.1. Pipelines created earlier keep
  taking the shape (`--no-review`, `--no-acceptance`, ...) from the command line.
- A `--doc` source must be committed and its revision pushed. Pass a directory when the design has appendices.
- `plan` commands print their exit-20 report on stdout, as `dag` and `work` commands already do.

## Fixed

- A resumed `plan` can no longer reset a running DAG's node state, and `--restart-active` acts on the stage that is stuck.
- A machine-gate budget stop and an author Run that ended without submitting are recoverable.
- Stops that had no runnable `next_action` have one; each is covered by a test that parses it with the real CLI.
- The `--no-review` flag no longer bypasses a review decision.

## Stopped by 2.0.x

An issue stopped on nits by 2.0.x (`review-nits-budget-exhausted`) is released by `omac plan continue-review --dag-key
<stage-key>` and `omac plan resume --plan-id <id>`; the Reviewer reviews again, and `omac plan accept-nits` accepts the
nits if the verdict is still `pass-with-nits`.
