# oh-my-multica v2.2.0

A minor release: the plan pipeline's human gate no longer waits for a person, it stops like every other plan stop; a
stage at the gate can be returned to its author; and a replaced `--doc` source reaches the author and the Reviewer.

## Behavior to know

- **The human gate is a stop.** With `workflow.human_in_loop` on, a plan or acceptance stage that passed review ends
  `plan create` / `plan resume` with exit 20 (`confirmation-required`) instead of polling until somebody moves the issue
  to Done. The report prints `next_action` (`omac plan confirm --dag-key <stage-key>`), `alternatives` (the same with
  `--reject --reason "<what to change>"`) and `then` (`omac plan resume --plan-id <id>`). `plan confirm` no longer makes a
  running process continue: run `plan resume` afterwards. Callers that kept a `plan create` process alive and ran
  `plan confirm` from elsewhere must now run the printed commands in sequence.
- **New: `omac plan confirm --reject --reason <text>`** returns the stage to its author. The reason is the author's rework
  input (`context.machine_feedback` in `omac work show`); a person's return is not counted as a review round.
- **A replaced `--doc` source is handed on as facts.** When `plan resume --doc` publishes a changed source, the stage that
  is redone gets a source-change section in its issue body (previous and current revision, a bounded diff of the source
  set), and its Reviewer gets a `source-change:plan` obligation, marked `delivery_unchanged: true` when the delivery is
  byte-identical to the previous one.

## Fixed

- A `--no-review` pipeline with the human gate on can be resumed after the confirmation (the confirmation no longer requires
  a Reviewer verdict when no Reviewer ran).
