# oh-my-multica v3.0.0

A major release. Planning checks the interfaces between nodes, a defect that a finished upstream node left behind becomes a fix
node instead of an exit-20 dead end, and a long-running DAG can wait for a person without giving up the manifest lock. Exit
codes, existing `--output json` fields (only additions), the three ports and the layering baseline are unchanged. It also
contains the 2.4.1 fix (`node accept` / `node abandon` retire the decision and handoff they answer).

## Behavior to know

- **Typed interfaces.** An artifact can declare `provides: [{id, ref}]`, a consumer `requires: [id]`; lint rejects a `requires`
  the producer does not provide and a registry guard that does not run after every registrant, with a YAML snippet to paste.
  Reviewers get `interface:*`, `registry:*` and `trace:refs` obligations; a `pass` must cite a path or a test name.
- **Acceptance v3.** `requirements` and `action.requirement_ids`; every in-scope action requirement must be referenced by an
  action and every `technical` requirement claimed by a node's `requirement_refs`.
- **Plan profile.** `light` (2.4 gates) or `standard` (typed `requires`, `ref`s, one closeout sink), decided by code from the node
  and business-action counts; only `plan.profile` overrides it. Plan stages also stop on a non-reducing machine gate and on a
  Reviewer whose evidence keeps failing the gate (`plan resume` releases both).
- **Upstream defects become fix nodes.** A Worker `upstream-defect` report (`omac.worker-blocker/v3`) is routed between two ticks.
  With `defects.auto_fix: design-gap` (default) a `fix.*` node is inserted through a system amendment (code-built, fixed whitelist,
  no Agent review, no person confirmation) and the reporter waits for it. Anything else stops with exit 20 and copyable commands.
  `omac defect list|report|grant` is the operator surface. **This changes the DAG by itself; `defects.auto_fix: off` turns it off.**
- **Waiting for a person.** `omac dag run --wait-decisions` releases the write lock while nothing runs and a decision is pending;
  `omac dag decisions` and `omac dag followups` are read-only. The closeout node's review must dispose of every follow-up.
- **Environment failures.** An `environment-failure` report is retried once by the same Worker (`retry.environment`), then exit 20
  with a command to switch Worker. `dispatch.hold_live` holds live nodes; `omac node retry --note` passes a note to the Worker.
- **Live nodes** are reviewed on the Worker's live evidence and the PR diff; the Reviewer does not rerun live-only commands.
- **Where state lives.** New `_dag.yaml` (audit schedule, defect ledger, pending human amendment, auto-held nodes); node state
  files gain `retry_note` and `defect_pending`. A running `dag run` reloads a definition file that someone else changed.

## Migrating from 2.4.x

1. Stop running `dag run` processes, upgrade omac on every machine that touches the manifest, restart. Do not mix versions on one
   manifest: a 2.x reader drops 3.0 fields without a warning.
2. Existing manifests keep working. `meta.reconcile_audit` moves to `_dag.yaml` on load; the first save rewrites the definition
   file once.
3. Re-propose any amendment reviewed under 2.x that was not accepted yet (the definition digest changed).
4. New configuration is optional: `retry.environment`, `defects.*`, `dispatch.hold_live`, `review.invalid_evidence_restarts`, `plan.*`.
5. Update custom role prompts: `upstream-defect` and `environment-failure` for Workers, evidence-based review for `live` nodes.

## Known limitations

- `_dag.yaml` can conflict on a multi-machine rebase; the system-amendment file is not synced between machines.
- `bounces.environment` is not reset by `node retry --worker`.
- The acceptance outer loop's inner ticks do not route defects; the next `dag run` does.
- Authoring recovery by system amendment was verified on a private Docker Multica only.
- Live evidence is enforced by Reviewer instructions, not by the evidence gate; evidence locators and `ref`s are checked for format only.
- `--wait-decisions` does not notice changes made only on the platform.
