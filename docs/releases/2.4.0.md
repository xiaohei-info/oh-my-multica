# oh-my-multica v2.4.0

A feature release: a node can be held, so work that is waiting on a person stops nothing else.

## Behavior to know

- **`omac node hold <manifest> <node> [--reason <text>]` / `omac node release <manifest> <node>`.** A held node is not
  dispatched even when its dependencies are done. Its downstream stays unsatisfied (not released, not `blocked`), and
  branches that do not depend on it keep advancing. Unlike `node abandon`, holding never lets a closing node behind it
  proceed early.
- **Only a `todo` node can be held.** A node already in progress is refused with a message (let it finish, or `abandon` it);
  a `blocked`/`failed` node must be `retry`-ed first.
- **Only held work left means exit 20.** With nothing running or failed, `dag run` / `dag tick` exit 20 with state `held`;
  the report lists `held_nodes` (key, reason), the `blocked_downstream` nodes and the `omac node release` commands. No new
  exit code.
- **Where it lives.** `held` / `hold_reason` are runtime facts in the node's state file (`.omac/<name>.state/<node>.yaml`);
  the manifest sync commits them, it never overwrites them. The commands take the manifest write lock: with a `dag run`
  active they exit 5, so stop the run, hold or release, then run again.
- `dag status`, `dag snapshot` and `node show` show `held` and `hold_reason`.
- No new configuration; existing JSON fields are unchanged.
