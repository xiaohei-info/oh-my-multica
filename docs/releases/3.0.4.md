# oh-my-multica v3.0.4

A fix release for stuck DAGs.

## Behavior to know

- **A Reviewer's `omac work submit` survives Multica's 8KB issue-metadata limit.** When the platform rejects a metadata write at
  the limit, OMAC shrinks the fields whose full value lives elsewhere (`source_refs`, old `reviewer_run_baseline` run ids, inline
  `review_obligations`) and retries once. Before, a develop node with many upstreams could never record a verdict, and each
  retry uploaded another copy of the report.
- **A node that was only isolated while waiting for a defect fix returns to `todo` once its upstreams are satisfied**, even when it
  already has a work item. A node that failed itself still needs `omac node retry`.
- **A defect whose fix node is done is `fixed` in the ledger** without waiting for another report.
- No new configuration; JSON fields and exit codes are unchanged.
