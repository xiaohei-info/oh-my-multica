# oh-my-multica v2.0.2

A patch release for the handoff from an author to its Reviewer.

## Fixed

- **Reviewer handoff while the author's Run is ending.** An author submits before its Run ends, often a minute or two
  earlier. OMAC treated that as an error: `omac plan create` and `omac plan resume` exited with "still waiting for the
  prior direct Run to finish", and on `dag run` the node could block or the tick could stop. The Reviewer is now assigned
  and woken once that Run has ended. The plan pipeline waits at its usual poll interval; `dag run` and `dag tick` retry on
  a later tick, without blocking the node or spending a retry budget.
- **`plan resume --doc` without `--name`.** The name now comes from the `doc-<plan-id>` source issue. `--name` is only
  required when that issue does not exist.

## Behavior to know

- While it waits, the plan pipeline logs one `review_handoff_wait` event; `dag run` and `dag tick` log one per tick.
- The wait lasts as long as the Run does. A Run that never ends is handled as before: `plan resume --restart-active`, or
  cancel it on the platform.
