# oh-my-multica v2.0.0

2.0.0 is a clean-up release. It removes everything that existed to recover one particular project, so what remains is the
general delivery process: plan a goal into a DAG, dispatch nodes to Agents through Multica, gate the results with machine
checks and independent review, merge, and repeat until the DAG converges and acceptance passes.

## Highlights

- **Smaller and clearer.** 17 project-specific modules, 17 recovery subcommands, 35 test files and 434 MB of captured
  fixtures are gone. The source is about 30,000 lines instead of 43,000.
- **Three ports.** `WorkItemStore`, `AgentRuntime` and `CodeHost` (pull requests, checks, merge). The pipeline depends on
  the ports; platform CLIs run only inside adapters. Layering is checked in CI.
- **Run state in small files.** One plain-text file per node, written only when it changes, synchronized through git.
  A tick on a 500-node DAG writes kilobytes; two machines advancing different nodes do not conflict.
- **Pure decisions.** Merge, Worker and Reviewer stage decisions are pure functions with table tests.
- **Real-server tests.** The test suite runs against a private Docker Multica with a scripted Agent, including a matrix
  that kills `omac` or loses the response after each write and checks nothing is done twice. About 2,700 tests run in
  roughly two minutes.

## Upgrading from 1.x

1. Finish or abandon any run that is still in progress with 1.x. 2.0 does not read 1.x state and says so (exit 5).
2. Install 2.0 and start new runs with `omac plan create`.
3. Replace `engine: mock` in scripts and configs: tests use a Docker Multica (`python -m pytest tests/it`).
4. If a script called one of the removed recovery subcommands, see the list in the [changelog](../../CHANGELOG.md).

## Install

```bash
pipx install git+https://github.com/xiaohei-info/oh-my-multica.git@v2.0.0
```

Requires Python 3.10 or later. The Multica engine needs the Multica CLI signed in to your workspace.
