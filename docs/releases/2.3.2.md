# oh-my-multica v2.3.2

A patch release: a concurrent write to one work item no longer stops the whole delivery loop.

## Behavior to know

- **An optimistic-read conflict skips one node for one tick.** When a Worker or Reviewer writes a work item while the Loop
  is reading it, the Loop used to fail the tick with a `PlatformError` (exit 2) and `dag run` stopped for every branch.
  Now the conflicting node is skipped, an `observation_conflict` event (node, item id, reason, streak) is logged, and the
  node is observed again on the next tick. Other nodes are processed normally; the tick's state and exit code follow them.
- **A conflict that does not clear is not silent.** After 5 consecutive ticks of one `dag run`, a single `warning` is logged
  for that node. The streak is in memory (one `dag tick` process starts at 1). There is no new stop state.
- **Unchanged:** real platform errors still fail the command with the same exit codes, and a persisted record that disagrees
  with the platform still fails closed. All platform writes still go through `apply`.
- No new configuration.
